# Система распределения задач между агентами для покупки билетов

Комплект для сдачи: FastAPI + PostgreSQL + WebSocket-агенты + простой пользовательский веб-интерфейс + админ-панель.

## Запуск

```bash
docker compose up --build
```

После запуска:

- Пользовательский интерфейс: http://localhost:8000/
- Админ-панель: http://localhost:8000/admin
- Swagger API: http://localhost:8000/docs

## Тестовые пользователи

- Администратор: `admin` / `admin`
- Пользователь: `user` / `user`

## Что входит

- `backend` - сервер FastAPI, REST API, WebSocket, планировщик, HTML-страницы.
- `db` - PostgreSQL.
- `agent_1` ... `agent_5` - пять консольных агентов, подключенных к серверу по WebSocket.

## Основная логика

- Заявки создаются пользователем и попадают в статус `queued`.
- Очередь сортируется по `admin_priority DESC`, затем `user_priority DESC`, затем `created_at ASC`.
- Свободные агенты получают задачи автоматически.
- Если свободных агентов нет, более приоритетная заявка может вытеснить менее приоритетную assigned-задачу.
- Вытесненная задача получает cooldown 30 секунд.
- Агент отправляет heartbeat каждые 30 секунд.
- Если heartbeat отсутствует более 2 минут, агент считается offline, а его задача возвращается в очередь.

## Быстрая проверка

1. Запустить `docker compose up --build`.
2. Открыть `/admin`, войти как `admin/admin` и проверить 5 агентов.
3. Открыть `/`, войти как `user/user`, создать заявку.
4. Вернуться в админку и поменять `admin_priority` у заявки.
5. Убедиться, что статус заявки меняется: `queued` -> `assigned` -> `completed` или `failed`.
